# 宽范围自适应星际航行

> 后续更新：火卫一已接入真实网格碰撞和着陆，火星近地前加入外部干预剧情，见 [MarsAccess.md](MarsAccess.md)。下文“火星 / 火卫一无碰撞”描述为该版本验证时的状态。

本说明取代 `CruiseApproach.md` 中的旧速度算法。具体配置保存在 `L_SpaceWorld`，可通过 `Tools/Editor/validate_multi_body_flight.py` 的 `configure` 操作重现。没有新增运行时系统；现有 `CompressedSpaceComponent` 计算通用速度场，服务器飞行组件应用实际推进，关卡配置具体天体参数。

## 调整原则

- 减速范围与衰减强度独立。不得通过收窄范围修复末段过慢。
- 当前五个天体全部使用完整几何半径的 80 倍作为近地边界外的过渡宽度，并保存该宽度下限。放大模型后范围按半径继续增加；缩小模型或改变曲线强度不会移除已保留的范围。
- 保留范围还覆盖上一版物理范围，以及历史导航减速门限的完整范围。迁移工具分别反求六个坐标方向的旧门限边界，利用单调、可分离 NAV 映射求保守包围球，验证新区域包含旧区域。这个计算只用于编辑器迁移和验证；运行时推进不依赖标记门限。
- 月球、地球碎块、火卫二、未标记的火星与火卫一全部参与。是否显示导航标记、镜头朝向、FOV 和遮挡均不影响推进。火星、火卫一仍没有碰撞、重力、着陆或地表玩法。

`FlightTransitionMinimumWidth` 是关卡保存的宽度下限；`FlightTransitionDistanceRadii` 是半径比例。运行时宽度为二者较大值。重新配置工具也会保留原有下限，避免重复运行时把已有范围覆盖为更小的值。

## 宽范围内的曲线

设 `p = clamp((中心距 - 完整半径 - 近地高度) / 过渡宽度, 0, 1)`，`k` 为曲线强度：

```
u = p / (p + k * (1-p))
t = smoothstep(0, 1, u)
基础速度倍率 = lerp(适配近地倍率, 巡航倍率, t)
```

本关卡 `k=0.1`，使用实际速度的算术插值，宽区域外缘较轻地减速，接近末段逐步接入近地速度。避免在约 100:1 的速度跨度中用对数插值制造较长低速尾段。两端斜率为零，强度变化不会改变区域宽度。`PlanetAnchor` 的现有强度覆盖值用于真实星球；背景天体使用条目中的 `FlightApproachExponent`。

[Reynolds 的 Arrival 行为](https://www.red3d.com/cwr/steer/gdc99/) 将开始减速距离作为独立参数；[Microsoft smoothstep 文档](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-smoothstep) 描述平滑 Hermite 插值。80 倍半径和 0.1 强度是本项目的体验参数，来自关卡验证，不是这些资料给出的通用最佳数值。

## 几何放大与缩小自适应

每个天体使用与实际表现相同的 `VisualScale` 和捕获的完整半径求视直径 `θ`，再沿推进方向中心采样，估计 `abs(dθ/ds)`。采样跨度采用天体半径与近地高度较大值的 15%，提前感知变化，避免抵达厘米级压缩导数尖峰后才骤然减速。压缩表现的变化也计入，不能只用完整半径除以物理距离。使用绝对值使同一路径的进出方向得到相同修正。

多方向扫描还发现，旧表现映射可能在近地前约一米内完成大幅放大，即使普通近地速度仍可产生数百度每秒的变化；地月重合坐标带还会把月球的变化点推到更远的斜向位置。视觉外壳取 `max(近地半径 + 4*完整半径, 最近天体中心距 / 2)`，在固定外壳位置采样天文远景比例，再向完整近地模型 smoothstep 衔接。避免继续混入当前位置的 NAV 导数尖峰。完整近地模型以及该过渡之外的天文远景保持原比例，地月互看校准点处于此范围之外。

设 `N` 为近地倍率，`B` 为基础倍率，`V` 为未按 Shift 加速的当前输入速度：

```
变化预算 = sqrt(radians(8)^2 + (0.65 * θ)^2)
负荷 = (B-N) * V * abs(dθ/ds) / 变化预算
单天体倍率 = N + (B-N) / sqrt(1 + 负荷^2)
```

绝对变化量与相对变化量共同调节；小圆盘和占据大视野的天体不共用一个生硬限速。它是额外巡航速度的柔和饱和，不会压低适配后的近地操作速度，也不声称是严格角速度上限。参考[视运动研究中的视直径及变化率](https://pmc.ncbi.nlm.nih.gov/articles/PMC3171144/)；此处是适用于游戏压缩场景的工程调校，不作真实航天控制或精确碰撞时间估计。

Shift 在普通输入查询所得倍率上应用飞船原有加速比例；不会被几何修正吃掉。横移、倒退、升降仍使用各自输入速度；Shift 不会意外提高未加速的横移速度。松键立即停止。

## 多天体融合及近地

每个覆盖当前位置的天体先算出自己的倍率，再共同加权对数平均。权重由到近地球的相对距离与区域进度连续计算：

```
w = (1 - smoothstep(p))^2 * (近地球半径 / max(近地球半径, 中心距))^4 * (1 + 负荷^2)
最终倍率 = exp(sum(w * log(单天体倍率)) / sum(w))
```

结果位于所有参与倍率之间，不选择某一个参考天体，也不把多个减速乘起来。近处天体平滑占主导，避免宽地球减速带把月球近地速度拉高；快速变化的小天体增加自身权重，避免火卫一的视觉放大被宽火星影响覆盖。三个以上天体也使用同一个归一化计算。候选速度的算术插值与多天体结果的对数平均承担不同职责。

地球、月球和火卫二继续使用 `PlanetAnchor` 的尺寸适配。背景天体也按完整半径、参考半径、尺寸指数和倍率上限计算，不再给火星写一个固定近地倍率。当前参考半径：月球 14,000 cm，其余 21,000 cm；指数 0.5，上限 3。具体属性由关卡保存，C++ 不引用具体星球 Actor。

近地跨越仍做球形入口裁剪，碰撞、碎块安全包络及服务器驾驶权限继续由原组件处理。巡航积分同时限制放大和缩小的单步变化，避免长帧跨过变化带。

## 编辑器与验证

停止 PIE 后，通过项目 Unreal MCP 调用 `SpaceDebugAuthoringTools.run(operation="multi_body_configure")`，仅修改并保存飞行参数。不要用完整场景重建工具代替该入口。手动调节位置为 `SpaceWorldManager → CompressedSpace → Bodies` 及三个 `PlanetAnchor` 的近地/曲线参数。

验证入口：`multi_body_envelope_scan`（五天体、26 个方向、双向修正与旧范围包含）、`multi_body_matrix`（全部 20 条有向路线）、PIE 中的 `multi_body_moon_native` 与 `multi_body_native`（驾驶者服务器 RPC、原生 Tick、原生相机）。`multi_body_status` 查看进度，`multi_body_report` 汇总结果。输出位于 `Saved/SpaceDebug/adaptive_*.json`。

自动化包括 `AdaptiveFlightEnvelope` 的宽度保持、尺寸比例、背景近地、实际几何调速、双向对称、Shift 比例和横移检查，以及原有多天体、碰撞、起降、HUD 包络回归。编译使用现有 `spaceEditor Win64 Development`，关闭编辑器，不使用 Live Coding。
