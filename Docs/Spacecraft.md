# 飞船系统

## 驾驶与起落

| 输入 | 行为 |
| --- | --- |
| W/S、A/D | 前后 / 横向推进 |
| Space、Ctrl | 上升 / 起飞、下降 / 自动着陆 |
| Shift、Q/E | 加速、滚转 |
| 方向键、T | 偏航 / 俯仰、180 度转向 |
| Alt、鼠标中键、滚轮 | 自由观察、视角回中、缩放 |
| R、L、鼠标左键 | 离船、前灯、飞船武器 |

多人共用同一艘飞船，最多四名乘员，只有驾驶员可发送飞行和武器意图。服务器检查乘员身份、状态、输入范围与有效期，再复制运动和模块表现。

自动着陆使用 PlanetAnchor 的真实表面和局部重力。支撑组件检查四脚、各脚多个样点、坡度与支撑有效性，避免只对中心点射线就判定可停泊。安全离地约束与脚架表现分别由对应组件承担，详见 [宇宙与近地飞行](SpaceWorld.md)。

## 组件与 Blueprint 配置

| 能力 | 主要组件 |
| --- | --- |
| 飞行与安全表面约束 | `JTSSpacecraftFlightMovementComponent` |
| 着陆支撑 | `JTSSpacecraftLandingSupportComponent` |
| 外观、脚架与推进表现 | `JTSSpacecraftPresentationComponent` |
| 船坞安装与服务 | `JTSShipDockComponent` |
| 实物分析 | `JTSShipScannerComponent` |
| 星际兑换 | `JTSStellarExchangeComponent` |
| 武器硬点与开火 | `JTSShipArmamentComponent` |
| 舱体连接与分离 | `JTSShipCabinCouplingComponent` |

船型、安装点、模型、服务 Blueprint 和模块初始清单由 Blueprint / Definition 配置。固定中央终端与可安装船坞分开管理；Required 与 Initial 模块清单也不是同一个含义。

## 停泊服务

飞船稳定停泊约 0.65 秒后部署船坞；收到起飞信号后收回，收回动画不阻塞起飞。

材料加工服务使用共享资源和加工图，服务器原子校验并提交配方。武器改装服务处理普通武器升级。中央终端提供采购、补给、成长和扫描货物入口。实际可用功能还需对应模块已安装且满足停泊条件。

## 扫描与仓储

扫描器附着于舱体组件，使用屏幕附近的实物收集区域。原生基准区域偏移为 `(0, 200, 0)` cm、半径 140 cm、高度 150 cm，最终以船型 Blueprint 为准。

服务器要求飞船已停泊、舱体已连接并具有真实地面支撑。未知物体按规格耗时约 3–16 秒，已识别物体约 1.2 秒。团队识别记录通过 DiscoveryComponent 复制，以类型 ID 而非每个尺寸实例登记。

样本在校验与预留成功前保留为世界实物。资源直接进入共享资源库；其他货物进入扫描货仓，原生容量 24。货仓满时仍可完成识别，但实物留在世界，不提前销毁。扫描货仓、共享资源、个人 30 格船柜和普通背包不能混为一个容量。

## 星际兑换机

兑换机是团队共享的付费实体服务，服务器检查资源、等级与成本表，按服务器时钟运行约 3.2 秒。待领奖记录绑定收件人稳定身份与令牌；奖励优先进入对应玩家的固件 / 装配存储，必要时通过世界弹出路径交付。

待发奖状态进入远征快照，恢复时避免重复支付或重复领奖。当前没有可自由取货的公共奖品库存；保留的 Stock 序列化字段不等于已经实现共享货架，TryClaim 路径当前不可用。

## 武器与舱体

武器模块通过通用硬点配置，使用当前驾驶员的意图。组件以服务器状态验证驾驶员、非着陆状态和输入时效；原生输入更新约 20 Hz，超过 0.3 秒的意图失效。炮口、激光模块、音效和表现由船型资产选择。

舱体组件提供 Docked、Releasing、Detached、Capturing 状态，服务端校验释放 / 捕获并复制状态与变换。Blueprint API 的存在不代表已有默认热键或独立驾驶舱飞行玩法，具体调用由项目配置决定。

飞船源美术在 `SourceArt/TwinforkR1`、`ShipRefit`、`ShipDocks`、`ShipAnalysis`；有用的外观与机构预览统一放在各自 `Previews` 子目录。
