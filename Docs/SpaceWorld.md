# 宇宙、尺度与导航

## 当前关卡

`/Game/Space/Maps/L_SpaceWorld` 当前注册五个真实天体：

| PlanetId | 归属组 | 当前导航图与屏幕标记 | 实际表面半径，约 cm |
| --- | --- | --- | --- |
| EarthFragments | EarthMoon | 显示 | 110009 |
| Moon | EarthMoon | 显示 | 15000 |
| Mars | MarsSystem | 显示 | 49561 |
| MarI | MarsSystem | 隐藏 | 18000 |
| MarII | MarsSystem | 隐藏 | 18207 |

MarI / MarII 的显示开关不关闭碰撞、重力、表面查询或近地飞行。不能把导航图只显示三个目标解释为关卡只有三个天体。当前 SpaceWorldManager 的 InitialPlanetId 为 Mars；常规出生与旅行最终仍由 GameMode / 快照决定。

## 三种尺度用途

PlanetAnchor 定义真实玩法表面。导航配置单独保存参考距离与半径；压缩空间把这些参考关系映射到可玩的显示距离和尺寸。不要用导航公里值直接替代真实 Mesh 尺寸，也不要因远景视觉缩放修改资源密度、角色尺度或着陆支撑。

`UJTSCompressedSpaceComponent` 按 EarthMoon / MarsSystem 组处理远近过渡，让组内天体相对关系与模型尺度协同变化。切换依赖当前局部星系、组范围、过渡距离和迟滞，不是让每颗卫星各自任意漂移。地月天空与火星卫星景观需要结合当前组变换判断，不能沿用早期独立气泡方案的结论。

## 近地飞行与边界

飞行先满足真实表面安全距离，再应用远距接近和近地速度调节。当前五个天体都启用近地飞行；共享参考半径 21000 cm、最大倍率 3、指数 0.5。远距接近还由过渡半径、角直径及相对距离控制，不把某一颗星球写成飞行组件中的特例。

飞船的避地、自动着陆和起落支撑使用实际天体表面。当前配置保留天体干扰能力，但五个 Body 的干扰开关均关闭；因此不能继续把旧“接近火星必定拦截 / 弹回”的方案当作现行玩法。火星权限卡与具体遭遇进度另行管理，不凭旧干扰文档推断权限效果。

## 导航图

导航支持地表视图、局部星系视图与宇宙层级转换。当前设置的切换时长为 1.4 秒，使用范围与迟滞避免视图在边缘反复切换。

地表图由表面颜色与深度捕获生成，结合 `/Game/Space/UI/Navigation/M_SurfaceMapRelief` 表现地形起伏，不是只贴一张 BaseColor。当前捕获分辨率 512、地表半宽 6000 cm、捕获高度 20000 cm。捕获与标记由导航组件和星球配置提供，不应修改原始星球 Mesh 来生成地图。

宇宙图和局部图的距离标签使用导航参考；它们不承诺等同于压缩场景中直接测量的距离。修改半径、卫星位置或组边界时，应一起检查远景、近地飞行、着陆与导航层级。

## 调试旅行

当前 DebugTravelManager 配置 Moon、Mars 两个目的地。调试跳转面向房主 / 服务器，偏好保存到独立 `JumpToSpaceDebugPreferences.sav`，Shipping 中禁用。它不能替代正常旅行、权限或共享快照恢复。

修改或验证入口主要位于 `Tools/Editor` 的导航、压缩空间和飞行脚本，以及 `Tools/Art/configure_mars_system.py`。这些是编辑器辅助工具；脚本中的历史常量可能早于当前关卡，不应无条件重跑配置脚本。
