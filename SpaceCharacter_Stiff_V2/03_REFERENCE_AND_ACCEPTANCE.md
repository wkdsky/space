# 参考判读、验证与完成标准

## 用户截图是否够用

足够确定风格和本次设计方向。图 1-4 提供骨名、参考姿态和手指长线等线索；图 5 明确左右交替拳的轮廓；图 6 明确外撇折腿跑。它们不能给出完整蒙皮权重、本地骨轴、动画接线或运行时父子关系，因此工程实现仍必须通过 Unreal 读取真实资产。

## 本版相较旧版

- 撤销默认松肩晃胯、垂腕滞后和自然拳击的方向。
- 步行改为固定肘腕的杆状摆臂；跑步以用户图 6 为主体，空手上臂保持折角。
- 拳击改为图 5 的僵直快速交替，躯干几乎不转。
- 完全移除旧包的跳跃设计及跳跃实施要求。
- 持物上身不再重新设计，只验证新腿部动作的兼容。
- 增加固定坐标技术图、相位数据和循环预览，避免靠透视效果图推断左右动作。

## 官方实现依据

本版动作造型和数值是独立设计。下面两项仅支持工程实现方法，不构成用户真实工程已经实现的证据：

1. Epic：Using Layered Animations，说明可按骨骼分层组合下身移动与上身动作；Slot 名称本身不自动限定上身。
   https://dev.epicgames.com/documentation/en-us/unreal-engine/using-layered-animations-in-unreal-engine
2. Epic：Two Bone IK，求解使用末端及其上方两级父骨构成的链，需要核查实际层级和求解方向。
   https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-two-bone-ik-in-unreal-engine

## 必须由 Grok 执行的验收

下列游戏内项目目前全部未测试；设计包的本地检查不代表 UE 实测。

- [ ] 真实 Pawn 的 Mesh/AnimClass/Slot/Rig/动画资产绑定已确认；动作在运行中可见。
- [ ] W0-W3 左右顺序正确，走路不合手、不交叉腿、腕部无松垮延迟。
- [ ] R1/R3 确实一侧支撑、另一膝外撇折腿；不是双腿同时跳。
- [ ] 跑步空手肘在腰肋附近、固定折角，不变成肩高翅膀或甩腕。
- [ ] B0/B2 是相反手向前伸出；拳在胸肩高度，不向天空举手。
- [ ] 拳击头胸稳定，快速连续，端点不过伸、不跨中线、不靠瞬移换姿态。
- [ ] 走/跑/停、转向、倒退、侧移、斜坡与台阶接地正常，实际移速未改变。
- [ ] 同时移动和出拳按原规则可用，松开与切物后恢复正确上身。
- [ ] 攻击有效窗口覆盖前冲路径，服务器结算去重，客户端确认不重复播拳或扣血。
- [ ] 持枪、单手和双手物品在新腿部动作下仍稳定，空手上身层不污染持物。
- [ ] 跳跃相关资产和参数未被改写；起跳/空中/下落/落地画面与基线一致。
- [ ] 若调整骨骼或约束，验证所有既有跳跃和持物表现，没有新蒙皮爆点。
- [ ] 至少两个联网角色互相观察走跑和拳击；记录实际网络条件和结果。
- [ ] 验证攻击期间专服骨骼/命中更新（如工程支持专服）；没有测试就明示。
- [ ] 交付修改文件和资产路径、真实运行录像、参数入口、未完成项和回退步骤。

## 包内数据核对方法

`source/build_pose_sheets.py` 在生成时检查全部参考样本的大腿、小腿、上臂、前臂长度保持不变。四张技术图、SVG、PDF 与 GIF 均使用同一生成函数。关键帧 CSV 的角度由对应三维坐标算出，不是从概念图人工猜测。

这些检查只证明参考图内部的数据一致性，不证明用户网格无穿插、实际角色可达、网络同步或攻击命中已经通过。
